## Findings

### [CONTRADICTION FLAG] F1 — CRITICAL: Broken template file reference
**Files:** SKILL.md (lines 47, 158) vs filesystem
- SKILL.md Resource Map: `templates/hive-contract.md`
- SKILL.md Phase 4 text: "Use `templates/hive-contract.md` as the template."
- Actual file on disk: `templates/crucible-contract.md`
- `templates/hive-contract.md` does NOT exist.
- **Impact:** Phase 4 fails silently. Orchestrator reads a nonexistent file; contract generation breaks.

### [CONTRADICTION FLAG] F2 — CRITICAL: MiniMax models listed in Available Models table without harness clarification
**Files:** resources/model-harness-guide.md (lines 34–35)
- Available Models table lists `minimax/minimax-m2.7` and `minimax/minimax-m1` alongside Anthropic models in the same table
- The table has no column or note indicating these CANNOT be used via `Agent(subagent_type="general-purpose", model="minimax/...", ...)`
- They can ONLY be dispatched via Codex CLI
- An orchestrator reading the top table alone (before reaching the Codex CLI section) will attempt `Agent(..., model="minimax/minimax-m2.7", ...)` — which will fail
- **Impact:** Incorrect agent spawning; silent execution failure

### [CONTRADICTION FLAG] F3 — Structural Designer: Sonnet vs Opus contradiction
**Files:** resources/model-harness-guide.md vs resources/agent-roster.md
- model-harness-guide.md "Default: Sonnet 4.6" table includes: `Structural Designer | Organizing a document structure`
- agent-roster.md Structural Designer entry: `**Model:** Opus 4.6 (structure cascades to everything)`
- Two authoritative sources, directly contradicting each other on the same role.
- **Impact:** Non-deterministic model assignment depending on which file the orchestrator reads last

### [CONTRADICTION FLAG] F4 — Contract template: A2A_STATUS vs A2A_ENABLED variable mismatch
**Files:** templates/crucible-contract.md (lines 160–162)
- Line 160: `A2A Status: {{A2A_STATUS}}` (display placeholder)
- Line 162: `{{#if A2A_ENABLED}}` (conditional block uses DIFFERENT variable name)
- Compare with templates/agent-brief.md (lines 79, 83): both use `{{A2A_ENABLED}}` consistently
- If contract is filled with `A2A_STATUS=true` but `A2A_ENABLED` is not set, the if-block doesn't evaluate
- **Impact:** A2A section in contract silently renders as disabled even in Hybrid Wave mode

### [CONTRADICTION FLAG] F5 — shutdown_request dict syntax: JS object vs Python dict
**Files:** resources/coordination-modes.md (line 73) vs SKILL.md (line 224)
- coordination-modes.md: `SendMessage(to="*", message={type:"shutdown_request"})`
  — JS object notation (unquoted keys)
- SKILL.md: `SendMessage(to="*", message={"type": "shutdown_request", "reason": "..."})`
  — correct Python dict with quoted keys
- Python dicts require quoted keys. JS-style `{type:"..."}` is a syntax error in Python.
- **Impact:** Orchestrators copying the coordination-modes.md snippet get a Python SyntaxError at teardown

### [ASSUMPTION] F6 — --skip-git-repo-check flag inconsistency
**Files:** resources/model-harness-guide.md Codex CLI table (lines 129–135)
- MiniMax rows include `--skip-git-repo-check`
- ALL other rows (GPT-4.1, Gemini, Grok, GPT-5.5) do NOT include `--skip-git-repo-check`
- Hive runs in the HappyCapy workspace which is not a git repo → Codex fails without this flag
- The inconsistency means non-MiniMax Codex dispatches fail in the standard workspace
- **Impact:** All non-MiniMax Codex CLI dispatches fail in non-git workspace (runtime error)

### [ASSUMPTION] F7 — Available Models table: Anthropic models lack gateway prefix in some files
**Files:** agent-roster.md, crucible-contract.md, SKILL.md quick reference, agent-brief.md example
- model-harness-guide.md uses `anthropic/claude-sonnet-4.6` (correct gateway prefix)
- All other files use `claude-sonnet-4.6`, `claude-opus-4.6`, `claude-haiku-4.5` (no prefix)
- For the Agent tool in Claude Code, both forms work (short names are resolved internally)
- For Codex CLI with model_provider=ai_gateway, the full prefix is required
- **Impact:** Low severity for Claude Code Agent tool; would matter if Anthropic models were dispatched via Codex

### [ASSUMPTION] F8 — Assignment Matrix "Codex CLI" in Harness column conflates two paradigms
**Files:** resources/model-harness-guide.md (lines 258–265)
- Assignment Matrix header: `Cognitive Demand | Harness | Model`
- Rows for MiniMax, Gemini, Grok, etc. list `Codex CLI` as the Harness
- But `Codex CLI` is not a harness — it's an external tool dispatched via Bash
- The four harnesses are: `general-purpose`, `Plan`, `Explore`, `Codex CLI` (per SKILL.md line 140–146)
- Including Codex CLI as a "harness" in the same classification as Agent subagent types conflates two different orchestration mechanisms
- **Impact:** Conceptual ambiguity; medium severity

### [ASSUMPTION] F9 — "Crucible" brand leak throughout all resource files
**Files:** All resources/* and templates/*
- Every file header/title says "Crucible": "Crucible Model & Harness Guide", "Crucible Universal Agent Roster", "Crucible Task Taxonomy", "Crucible Coordination Modes", "CRUCIBLE AGENT BRIEF", "Crucible Contract"
